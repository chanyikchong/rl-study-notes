# RLHF：基于人类反馈的强化学习

## 面试摘要

**RLHF** 通过三步流程将语言模型与人类偏好对齐：(1) 监督微调（SFT），(2) 奖励模型训练，(3) RL优化。核心挑战是最大化奖励的同时通过KL正则化防止奖励黑客攻击。存在多种算法：**TRPO**（2015）提供理论保证，**PPO**（2017）通过裁剪简化，**DPO**（2023）消除奖励模型，**GRPO**（2024）使用基于组的优势估计。

---

## 为什么用RL训练LLM？

### 对齐问题

预训练LLM学习预测下一个token，但这不能保证：
- 有帮助、无害、诚实的回答
- 准确遵循指令
- 避免有害内容

**监督微调（SFT）** 本身有局限性，因为：
1. 收集专家演示数据成本高
2. 模型可能只是记忆而不理解意图
3. 难以为所有情况指定"好"的回答

### RLHF流程

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                           RLHF 流程                                         │
└─────────────────────────────────────────────────────────────────────────────┘

第一步：监督微调（SFT）
┌──────────────┐    ┌─────────────────┐    ┌──────────────┐
│ 基础 LLM     │ →  │ 在演示数据上    │ →  │ SFT 模型     │
│ (预训练)     │    │ 微调            │    │ π_SFT        │
└──────────────┘    └─────────────────┘    └──────────────┘

第二步：奖励模型训练
┌──────────────┐    ┌─────────────────┐    ┌──────────────┐
│ 收集         │ →  │ 训练预测        │ →  │ 奖励模型     │
│ 偏好数据     │    │ 人类偏好        │    │ r_φ(x, y)    │
│ (y_w > y_l)  │    │                 │    │              │
└──────────────┘    └─────────────────┘    └──────────────┘

第三步：RL优化
┌──────────────┐    ┌─────────────────┐    ┌──────────────┐
│ SFT 模型     │ →  │ 使用            │ →  │ 对齐后的     │
│ π_SFT        │    │ PPO/DPO/GRPO    │    │ LLM π_θ      │
└──────────────┘    └─────────────────┘    └──────────────┘
```

## 核心RLHF目标

所有方法都旨在最大化期望奖励，同时保持接近参考策略：

$$\max_{\pi_\theta} \mathbb{E}_{x \sim \mathcal{D}, y \sim \pi_\theta(y|x)} \left[ r_\phi(x, y) \right] - \beta \cdot D_{KL}\left(\pi_\theta \| \pi_{ref}\right)$$

其中：
- $\pi_\theta$：正在优化的策略（LLM）
- $\pi_{ref}$：参考策略（通常是SFT模型）
- $r_\phi(x, y)$：对提示$x$的回答$y$的奖励模型分数
- $\beta$：KL惩罚系数（防止奖励黑客攻击）

### 为什么需要KL惩罚？

没有它，模型可能利用奖励模型的弱点：

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                         奖励黑客攻击                                        │
└─────────────────────────────────────────────────────────────────────────────┘

没有KL惩罚：
┌─────────────────────────────────────────────────────────────────────────────┐
│  策略发现奖励模型的"漏洞"：                                                  │
│  - 得高分的重复短语                                                          │
│  - 谄媚式回答（"好问题！"）                                                  │
│  - 技术上高奖励但无意义的输出                                                │
│                                                                             │
│  结果：高奖励，但无用或有害的回答                                           │
└─────────────────────────────────────────────────────────────────────────────┘

有KL惩罚：
┌─────────────────────────────────────────────────────────────────────────────┐
│  策略必须保持接近SFT模型：                                                   │
│  - 不能偏离太远                                                              │
│  - 奖励的平衡改进                                                            │
│  - 保持语言连贯性                                                            │
│                                                                             │
│  结果：真正提高有帮助性/安全性                                               │
└─────────────────────────────────────────────────────────────────────────────┘
```

## RLHF方法演进

该领域从复杂的约束优化演进到更简单、更实用的方法：

```
RLHF方法时间线：
═══════════════════════════════════════════════════════════════════════════════

2015 ─── TRPO（信任域策略优化）
         │
         │  理论基础：单调改进保证
         │  问题：复杂（Fisher矩阵、共轭梯度、线搜索）
         │
         ▼
2017 ─── PPO（近端策略优化）
         │
         │  简化TRPO：用裁剪代替约束
         │  成为RLHF的默认选择（InstructGPT、ChatGPT使用）
         │
         ▼
2023 ─── DPO（直接偏好优化）
         │
         │  关键洞察：完全跳过奖励模型！
         │  直接在偏好对上优化
         │  更简单的流程，但灵活性较低
         │
         ▼
2024 ─── GRPO（组相对策略优化）
         │
         │  不需要评论家网络
         │  基于组的优势估计
         │  用于DeepSeekMath
         │
         ▼
      ... 更多方法涌现（KTO、IPO、ORPO等）

═══════════════════════════════════════════════════════════════════════════════
```

## 方法对比一览

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                        方法对比                                              │
└─────────────────────────────────────────────────────────────────────────────┘

                    奖励模型?      评论家?       参考策略?
                         │             │              │
TRPO                    是            是            可选
                         │             │              │
PPO                     是            是            是（用于KL）
                         │             │              │
DPO                     否            否            是（必需）
                         │             │              │
GRPO                    是            否            是（用于KL）
```

### 详细对比

| 方法 | 年份 | 关键创新 | 优点 | 缺点 |
|------|------|----------|------|------|
| [TRPO](trpo.md) | 2015 | 信任域约束 | 理论保证、稳定 | 复杂、昂贵 |
| [PPO](ppo.md) | 2017 | 裁剪代理 | 简单、有效、广泛使用 | 需要奖励模型+评论家 |
| [DPO](dpo.md) | 2023 | 隐式奖励 | 无需奖励模型、简单 | 灵活性较低、仅成对 |
| [GRPO](grpo.md) | 2024 | 组归一化 | 无需评论家、灵活 | 需要多个样本 |

### 何时使用各方法

| 场景 | 推荐 | 原因 |
|------|------|------|
| 通用RLHF | PPO | 经过充分测试、灵活 |
| 计算资源有限 | DPO | 无需训练奖励模型 |
| 可验证任务（数学/代码） | GRPO | 基于结果的奖励 |
| 最大稳定性 | TRPO | 保证改进 |
| 离线偏好数据 | DPO | 无需在线采样 |

## 各方法详细页面

每个方法都有独立的详细页面：

1. **[TRPO](trpo.md)** — 信任域策略优化（2015）
   - 策略优化的理论基础
   - 单调改进保证
   - 自然梯度和Fisher信息矩阵

2. **[PPO](ppo.md)** — 近端策略优化（2017）
   - 裁剪代理目标
   - 完整Actor-Critic实现
   - PPO用于RLHF的细节

3. **[DPO](dpo.md)** — 直接偏好优化（2023）
   - 绕过奖励模型
   - 隐式奖励推导
   - Bradley-Terry模型联系

4. **[GRPO](grpo.md)** — 组相对策略优化（2024）
   - 基于组的优势估计
   - 无需评论家
   - 与排序损失的联系

## 关键公式总结

| 方法 | 核心公式 |
|------|----------|
| **RLHF目标** | $\max_\pi \mathbb{E}[r(x,y)] - \beta D_{KL}(\pi \|\| \pi_{ref})$ |
| **TRPO** | $\max L^{CPI}$ s.t. $D_{KL} \leq \delta$ |
| **PPO** | $L = \min(r_t A_t, \text{clip}(r_t, 1\pm\epsilon) A_t)$ |
| **DPO** | $L = -\log\sigma(\beta(r_w - r_l))$ 其中 $r = \log\frac{\pi_\theta}{\pi_{ref}}$ |
| **GRPO** | $A_i = (r_i - \mu) / \sigma$（组归一化） |

## 测验

<details>
<summary><strong>Q1：RLHF流程的三个步骤是什么？</strong></summary>

**答案**：
1. **监督微调（SFT）**：在演示数据上微调基础LLM
2. **奖励模型训练**：训练模型从比较数据中预测人类偏好
3. **RL优化**：使用PPO/DPO等最大化奖励，同时保持接近SFT模型

</details>

<details>
<summary><strong>Q2：为什么RLHF中需要KL惩罚？</strong></summary>

**答案**：KL惩罚防止**奖励黑客攻击**——模型利用奖励模型的弱点产生高奖励但无意义或有害的输出。通过保持策略接近SFT模型，我们确保模型保持语言连贯性，只进行真正的改进。

</details>

<details>
<summary><strong>Q3：DPO相对于PPO的主要优势是什么？</strong></summary>

**答案**：DPO**消除了对奖励模型的需求**。DPO不是训练单独的奖励模型然后进行RL，而是直接在偏好对上优化策略。这简化了流程，避免了奖励模型质量的潜在问题。

</details>
