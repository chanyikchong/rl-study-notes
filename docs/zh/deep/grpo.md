# GRPO：组相对策略优化（2024）

## 面试摘要

**GRPO** 通过从对同一提示的**一组回答**中估计优势来消除对评论家网络的需求。对于每个提示，采样 $G$ 个回答，计算奖励，然后归一化：$\hat{A}_i = (r_i - \mu) / \sigma$。这是组内的**相对排名**——不需要学习的价值函数。GRPO使用PPO的裁剪目标，但使用组归一化的优势。对于具有**可验证奖励**的任务（数学、代码）特别有效，其中正确性提供奖励信号。

**需要记住的**：组优势公式 $\hat{A}_i = (r_i - \mu) / \sigma$，为什么它消除评论家，与排序损失的联系。

---

## 动机

GRPO（Shao等，2024）解决了现有方法的关键限制：

| 方法 | GRPO解决的限制 |
|------|----------------|
| **PPO** | 需要单独的评论家/价值网络（参数翻倍） |
| **DPO** | 仅限于成对偏好（只比较2个回答） |

**GRPO的解决方案**：使用一*组*回答作为自包含的基线——无需评论家，且可以处理任意数量的回答。

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                    LLM RLHF中的评论家问题                                    │
└─────────────────────────────────────────────────────────────────────────────┘

在经典RL中（Atari、机器人）：
┌─────────────────────────────────────────────────────────────────────────────┐
│  评论家 V(s) 从状态 s 预测未来奖励                                           │
│  • 状态是马尔可夫的（包含所有相关信息）                                      │
│  • 评论家学习有意义的价值函数                                                │
│  • 减少优势估计的方差                                                        │
└─────────────────────────────────────────────────────────────────────────────┘

在LLM RLHF中：
┌─────────────────────────────────────────────────────────────────────────────┐
│  "状态" = 提示 + 部分回答                                                    │
│  • 部分回答的"价值"是什么？                                                  │
│  • 奖励只在最后（非马尔可夫结构）                                            │
│  • 评论家常常难以学习有意义的价值                                            │
│  • 内存需求翻倍（评论家 = 另一个LLM大小的网络）                              │
└─────────────────────────────────────────────────────────────────────────────┘

GRPO洞察：完全跳过评论家！
```

## 核心思想

GRPO不使用学习的价值函数（评论家），而是从对同一提示的**一组回答**中估计优势。

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                        GRPO采样策略                                          │
└─────────────────────────────────────────────────────────────────────────────┘

对于每个提示 x，采样 G 个回答：

                              提示："2 + 2等于多少？"
                                        │
                    ┌───────────────────┼───────────────────┐
                    ▼                   ▼                   ▼
               回答 1               回答 2               回答 G
               "2 + 2 = 4"         "是4！"             "答案是..."
                    │                   │                   │
                    ▼                   ▼                   ▼
                 r₁ = 1.0           r₂ = 0.8           rG = 0.9
                    │                   │                   │
                    └───────────────────┼───────────────────┘
                                        │
                                        ▼
                              计算组统计量：
                              μ = mean(r₁, r₂, ..., rG)
                              σ = std(r₁, r₂, ..., rG)
                                        │
                                        ▼
                           优势 = (rᵢ - μ) / σ
```

## 基于组的优势估计

### 公式

对于每个提示 $x$，采样一组 $G$ 个回答：$\{y_1, y_2, ..., y_G\} \sim \pi_{\theta_{old}}(y|x)$

计算每个的奖励：$\{r_1, r_2, ..., r_G\}$ 其中 $r_i = r_\phi(x, y_i)$

**优势估计**：

$$\hat{A}_i = \frac{r_i - \text{mean}(\{r_j\}_{j=1}^G)}{\text{std}(\{r_j\}_{j=1}^G)} = \frac{r_i - \mu_G}{\sigma_G}$$

这是组内的**相对排名**——不需要绝对价值函数！

### 为什么这能工作

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                    为什么组归一化有效                                        │
└─────────────────────────────────────────────────────────────────────────────┘

1. 消除基线偏差
   ──────────────────────────────────────────────────────────────────────────
   问题：不同提示有不同的固有难度

   提示A："1+1等于多少？"   → 大多数回答得高分
   提示B："证明P≠NP"       → 大多数回答得低分

   没有归一化：提示A的回答总是看起来"更好"
   有归一化：只有提示内的相对质量重要

2. 归一化尺度
   ──────────────────────────────────────────────────────────────────────────
   问题：奖励幅度可能因提示/领域而异

   除以σ确保：
   • 组中最好的回答 ≈ +1 到 +2
   • 组中最差的回答 ≈ -1 到 -2
   • 一致的梯度幅度

3. 不需要评论家
   ──────────────────────────────────────────────────────────────────────────
   传统：A(s,a) = R - V(s)，其中V(s)是学习的
   GRPO：A(x,y) = (r - μ) / σ，其中μ,σ来自同批次

   组均值作为经验基线！
```

## GRPO目标

GRPO将PPO的裁剪目标与组归一化优势相结合：

$$\mathcal{L}_{GRPO}(\theta) = \mathbb{E}_{x} \mathbb{E}_{\{y_i\}_{i=1}^G \sim \pi_{old}} \left[ \frac{1}{G} \sum_{i=1}^{G} \min\left( r_i(\theta) \hat{A}_i, \text{clip}(r_i(\theta), 1-\epsilon, 1+\epsilon) \hat{A}_i \right) \right]$$

其中：
- $r_i(\theta) = \frac{\pi_\theta(y_i|x)}{\pi_{\theta_{old}}(y_i|x)}$ 是概率比（与PPO相同）
- $\hat{A}_i = (r_i - \mu_G) / \sigma_G$ 是组归一化优势
- $\epsilon$ 是裁剪参数（通常为0.2）

### 带KL正则化

为防止奖励黑客攻击：

$$\mathcal{L}_{GRPO}(\theta) = \mathcal{L}_{clip}(\theta) - \beta \cdot \mathbb{E}_{x, y \sim \pi_\theta} \left[ D_{KL}(\pi_\theta(y|x) \| \pi_{ref}(y|x)) \right]$$

## GRPO算法

```
GRPO算法：
═══════════════════════════════════════════════════════════════════════════════
输入：参考策略 π_ref，奖励模型/函数 r_φ，组大小 G，β

初始化：π_θ ← π_ref

for iteration = 1, 2, ... do:

    ┌─ 采样提示 ──────────────────────────────────────────────────────────────┐
    │  1. 采样一批提示：{x_1, ..., x_B} ~ D                                   │
    └─────────────────────────────────────────────────────────────────────────┘
                                      │
                                      ▼
    ┌─ 生成回答组 ────────────────────────────────────────────────────────────┐
    │  2. 对于每个提示 x_b：                                                   │
    │     生成 G 个回答：{y_b,1, ..., y_b,G} ~ π_θ_old(·|x_b)                │
    │     计算奖励：{r_b,1, ..., r_b,G} 通过奖励模型                          │
    │                                                                          │
    │     （对于数学等可验证任务，奖励可以是二值0/1）                          │
    └─────────────────────────────────────────────────────────────────────────┘
                                      │
                                      ▼
    ┌─ 归一化优势 ────────────────────────────────────────────────────────────┐
    │  3. 对于每个提示组：                                                     │
    │     μ_b = mean({r_b,i}_{i=1}^G)                                         │
    │     σ_b = std({r_b,i}_{i=1}^G) + ε  （加小ε保持稳定）                   │
    │     A_b,i = (r_b,i - μ_b) / σ_b                                         │
    └─────────────────────────────────────────────────────────────────────────┘
                                      │
                                      ▼
    ┌─ 计算策略比率 ──────────────────────────────────────────────────────────┐
    │  4. r_θ(y_b,i) = π_θ(y_b,i|x_b) / π_θ_old(y_b,i|x_b)                   │
    └─────────────────────────────────────────────────────────────────────────┘
                                      │
                                      ▼
    ┌─ 计算裁剪目标 ──────────────────────────────────────────────────────────┐
    │  5. L = (1/BG) Σ_b Σ_i min(r_θ A_b,i, clip(r_θ, 1-ε, 1+ε) A_b,i)       │
    └─────────────────────────────────────────────────────────────────────────┘
                                      │
                                      ▼
    ┌─ 添加KL惩罚 ────────────────────────────────────────────────────────────┐
    │  6. L_total = L - β · D_KL(π_θ || π_ref)                                │
    └─────────────────────────────────────────────────────────────────────────┘
                                      │
                                      ▼
    ┌─ 更新 ──────────────────────────────────────────────────────────────────┐
    │  7. θ ← θ + α∇_θL_total                                                 │
    └─────────────────────────────────────────────────────────────────────────┘

═══════════════════════════════════════════════════════════════════════════════
```

## GRPO vs PPO比较

| 方面 | PPO | GRPO |
|------|-----|------|
| **基线** | 学习的价值函数 $V_\phi(s)$ | 组奖励均值 $\mu_G$ |
| **网络** | Actor + Critic（2倍参数） | 仅Actor |
| **方差来源** | 评论家估计误差 | 组大小（更大G→更低方差） |
| **样本效率** | 可以重用样本（小心处理） | 每次迭代需要新鲜组 |
| **内存** | 策略 + 评论家 + 奖励模型 | 策略 + 奖励模型 |
| **最适合** | 通用RLHF | 可验证奖励任务 |

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                      内存比较                                                │
└─────────────────────────────────────────────────────────────────────────────┘

RLHF的PPO：
┌─────────┐ ┌─────────┐ ┌─────────┐ ┌─────────┐
│ 策略    │ │ 评论家  │ │ 奖励    │ │  参考   │
│  π_θ    │ │  V_φ    │ │  模型   │ │  π_ref  │
│ (7B)    │ │ (7B)    │ │ (7B)    │ │ (7B)    │
└─────────┘ └─────────┘ └─────────┘ └─────────┘
总计：~28B参数需要存储

GRPO：
┌─────────┐             ┌─────────┐ ┌─────────┐

│  π_θ    │             │  模型   │ │  π_ref  │

└─────────┘             └─────────┘ └─────────┘
总计：~21B参数（节省25%）
```

## 与排序的数学联系

GRPO的优势可以看作是**软排序损失**。考虑特殊情况 $G=2$：

如果我们有 $(y_w, y_l)$ 且 $r_w > r_l$：

$$\mu = \frac{r_w + r_l}{2}$$

$$\sigma = \sqrt{\frac{(r_w - \mu)^2 + (r_l - \mu)^2}{2}} = \frac{|r_w - r_l|}{\sqrt{2}}$$

因此：

$$\hat{A}_w = \frac{r_w - (r_w + r_l)/2}{|r_w - r_l|/\sqrt{2}} = \frac{(r_w - r_l)/2}{(r_w - r_l)/\sqrt{2}} = \frac{1}{\sqrt{2}} \approx 0.707$$

$$\hat{A}_l = -\frac{1}{\sqrt{2}} \approx -0.707$$

**关键洞察**：$G=2$ 时，GRPO退化为归一化的成对排序！无论奖励幅度如何，获胜者总是得到 $+\frac{1}{\sqrt{2}}$，失败者总是得到 $-\frac{1}{\sqrt{2}}$。

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                    GRPO作为广义排序                                          │
└─────────────────────────────────────────────────────────────────────────────┘

G=2：   等价于成对偏好（如DPO）
       获胜者：A = +1/√2，失败者：A = -1/√2

G=4：   对4个回答的软排序
       最好：A ≈ +1.5
       较好：A ≈ +0.5
       较差：A ≈ -0.5
       最差：A ≈ -1.5

G=16：  细粒度排序信号
       更多方差减少
       更好的优势估计
       但是：更多生成成本

权衡：更大的G → 更好的估计，更高的计算成本
```

## 何时使用GRPO

### 理想用例

1. **数学推理**（DeepSeekMath）
   - 二值正确性奖励（对/错）
   - 不需要主观判断
   - 易于验证

2. **代码生成**
   - 基于测试的奖励（通过/失败）
   - 确定性评估
   - 明确的成功标准

3. **内存受限设置**
   - 不需要评论家网络
   - 比PPO节省约25%内存

### 不太理想的用例

1. **主观质量**（有帮助性、创造性）
   - 需要学习的奖励模型
   - 奖励模型可能有噪声
   - 组归一化可能放大噪声

2. **低多样性回答**
   - 如果所有G个回答相似 → 小σ → 不稳定
   - 需要足够的探索

## 实践考虑

### 选择组大小G

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                      组大小权衡                                              │
└─────────────────────────────────────────────────────────────────────────────┘

小G（如2-4）：
├── 优点：更低的生成成本
├── 缺点：优势估计方差更高
└── 最适合：快速迭代、有限计算资源

中等G（如8-16）：
├── 优点：方差和成本的良好平衡
├── 缺点：中等生成开销
└── 最适合：大多数实际应用

大G（如32-64）：
├── 优点：低方差、稳定训练
├── 缺点：高生成成本
└── 最适合：最终训练运行、关键应用
```

### 处理边缘情况

```python
# 稳健优势估计的伪代码
def compute_advantages(rewards):
    mu = mean(rewards)
    sigma = std(rewards)

    # 处理低方差组
    if sigma < epsilon:
        # 所有奖励相似 → 没有有意义的排序
        # 选项1：跳过这个组
        # 选项2：使用原始中心化奖励
        return (rewards - mu)  # 未归一化

    return (rewards - mu) / sigma
```

## 测验

<details>
<summary><strong>Q1：GRPO解决了PPO在LLM设置中不能很好处理的什么问题？</strong></summary>

**答案**：GRPO消除了对**评论家（价值）网络**的需求。在LLM RLHF中，评论家是有问题的，因为：

1. **内存**：参数翻倍（评论家是另一个LLM大小的模型）
2. **语义**："部分回答的价值"是定义不清的
3. **训练**：评论家常常难以学习语言的有意义价值

GRPO用经验组均值 $\mu_G$ 替代学习的基线 $V(s)$，它直接从同提示回答计算。

**关键公式**：$\hat{A}_i = (r_i - \mu_G) / \sigma_G$ vs PPO的 $\hat{A}_t = R_t - V(s_t)$

</details>

<details>
<summary><strong>Q2：写出GRPO优势公式并解释为什么每项都是必需的。</strong></summary>

**答案**：

$$\hat{A}_i = \frac{r_i - \mu_G}{\sigma_G}$$

**各项**：
- $r_i$：回答 $y_i$ 的奖励（来自奖励模型或验证器）
- $\mu_G = \frac{1}{G}\sum_{j=1}^G r_j$：组均值——作为基线，消除提示特定难度
- $\sigma_G = \sqrt{\frac{1}{G}\sum_{j=1}^G (r_j - \mu_G)^2}$：组标准差——归一化尺度，确保一致的梯度幅度

**为什么减去均值？** 不同提示有不同的固有难度。中心化确保我们只学习相对质量。

**为什么除以标准差？** 奖励尺度可能变化。归一化防止某些提示主导梯度。

</details>

<details>
<summary><strong>Q3：证明G=2时GRPO等价于成对排序。</strong></summary>

**答案**：对于 $G=2$，奖励 $r_w > r_l$：

$$\mu = \frac{r_w + r_l}{2}$$

$$\sigma = \sqrt{\frac{(r_w - \mu)^2 + (r_l - \mu)^2}{2}} = \frac{r_w - r_l}{\sqrt{2}}$$

因此：
$$\hat{A}_w = \frac{r_w - \mu}{\sigma} = \frac{(r_w - r_l)/2}{(r_w - r_l)/\sqrt{2}} = \frac{1}{\sqrt{2}}$$

$$\hat{A}_l = \frac{r_l - \mu}{\sigma} = -\frac{1}{\sqrt{2}}$$

**关键洞察**：奖励差异的幅度消掉了！获胜者总是得到 $+\frac{1}{\sqrt{2}}$，失败者总是得到 $-\frac{1}{\sqrt{2}}$。这是纯成对排序——正是DPO用其隐式奖励做的。

</details>

<details>
<summary><strong>Q4：为什么GRPO特别适合数学推理任务？</strong></summary>

**答案**：数学推理任务有**可验证奖励**：

1. **二值正确性**：答案是对的或错的（没有主观判断）
2. **无奖励模型偏差**：真实结果提供奖励，而不是学习的模型
3. **清晰信号**：当采样G个回答时，正确的得r=1，错误的得r=0

组归一化自然创建排序：
- 如果3/8个回答正确：正确的得正优势，错误的得负优势
- 正确回答的比例不会偏置学习（感谢归一化）

**为什么PPO在这里更差**：评论家难以预测"部分数学解的价值"——价值取决于最终答案的正确性，这从中间步骤很难预测。

</details>

<details>
<summary><strong>Q5：你正在用GRPO训练，注意到损失不稳定，频繁出现NaN值。可能是什么问题，如何修复？</strong></summary>

**答案**：最可能的原因：**奖励组中方差低**。

当所有G个回答得到相似的奖励时（如全部正确或全部错误）：
- $\sigma_G \approx 0$
- 除以 $\sigma_G$ → 爆炸或NaN

**修复**：

1. **在分母加epsilon**：$\hat{A}_i = (r_i - \mu) / (\sigma + \epsilon)$ 其中 $\epsilon = 10^{-6}$

2. **跳过低方差组**：如果 $\sigma < \text{threshold}$，不在这批上更新

3. **增加温度**：用更高温度采样以增加回答多样性

4. **更大的G**：更多回答 → 更可能有方差

5. **检查奖励函数**：如果奖励裁剪太激进，方差消失

**调试策略**：记录每批的 $\sigma_G$ 值。如果很多接近零，增加多样性或调整奖励缩放。

</details>
